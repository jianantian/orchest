Supervised Delegation 模式是 Orchest 的核心验证 case 之一。

场景：主 Agent 将封装后的 Claude Code 作为 tool 调用，任务可能运行数小时甚至数天。主 Agent 通过 watcher LLM 持续消费工作 agent 的事件流，感知状态，适时注入指令或操作。

**Why:** 用户有实际产品需要此模式。它检验 runtime 的三个关键能力：异步长时 tool（`ToolOutput::AsyncJob`）、事件流消费（`RuntimeEvent`）、中途干预（Mid-run Steering）。

**How to apply:**
- 评估 v0.7/v0.8/v0.9 scope 时，以此 case 作为能力是否足够的判断标准
- AsyncJob poll 机制、Mid-run Steering、Hook 框架的设计都应考虑此场景
- Mid-run Steering 的优先级可能需要从 v0.9 提前，视实际验证需求决定
- 这是第三种 sub-agent 模式（区别于 Agent-as-Tool 和 Handoff），后续可能需要 runtime 层面的原语支持
