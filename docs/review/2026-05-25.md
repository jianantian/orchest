## 总体评估

v0.6 成功解决了 `run.rs` 4040 行单文件、`BudgetGuard` 硬编码定价、approval 路由竞争窗口等结构性债务。代码组织良好，类型系统运用得当，测试覆盖达到可接受基线。

以下问题按严重程度分四档。

## Critical（影响正确性或安全边界）

### C1. `agent-runtime-core` 反向依赖 `agent-runtime-providers`

**文件**：`crates/agent-runtime-core/Cargo.toml:19`，`crates/agent-runtime-core/src/model/mod.rs`

Core crate 通过 Cargo dependency + blanket re-export 依赖 providers crate 获取 `ModelAdapter` trait 和所有核心类型（`Message`、`ContentBlock`、`TokenUsage`、`StreamEvent` 等）。

**后果**：

- 编译 core 必须编译全部 4 个 provider adapter 实现（Anthropic 1600 行、OpenAI 816 行、DeepSeek 841 行、OpenRouter 887 行）
- 新增 provider 污染 core 编译图
- 类型来源语义错乱：`core::model::Message` 实际定义在 `providers::types.rs`

**建议**：抽取 `agent-runtime-model` crate，只含 trait + 纯数据类型。Core 和 providers 都依赖它。

### C2. Budget 检查丢弃违规原因

**文件**：`crates/agent-runtime-core/src/run/loop_.rs:147`

```rust
if let Some(_violation) = budget.check() {  // BudgetViolation 被丢弃
    emit(&tx, RuntimeEvent::RunFailed {
        error: "budget_exceeded".into(),     // 无法区分 token/cost/duration/tool_calls
    }).await;
}
```

`BudgetGuard::check()` 返回 `Option<BudgetViolation>` 枚举（4 个变体），但被 `_violation` 丢弃，`RunFailed.error` 只有通用字符串。

**建议**：`format!("budget_exceeded: {violation:?}")`。

### C3. `SkillEnvManager` 缺少显式 `Clone` derive

**文件**：`crates/agent-runtime-core/src/skill/mod.rs:129`，`bundled_tool.rs:405`

`SkillEnvManager` 不 derive `Clone`，但 `SkillBundledTool::clone_for_poll()` 调用 `self.env_manager.clone()`。当前因 `PathBuf` 是 field-wise `Clone` 的而编译通过，但依赖隐式行为——添加新字段（如 `Mutex`）会直接 break。

## High（影响可靠性或可维护性）

### H1. 无优雅取消机制

**文件**：`crates/agent-runtime-core/src/run/handle.rs`，`mod.rs`

`RunHandle` 暴露 `wait()` 但无法取消运行中的 agent。Drop event receiver 只能让 run loop 阻塞在 `tx.send().await`（channel 满后），不会终止。

**建议**：`tokio::sync::CancellationToken` 或 `watch` channel，循环顶部检查。

### H2. Node SDK 每次调用创建新 Tokio Runtime

**文件**：`crates/agent-runtime-node/src/lib.rs:325, 387, 422`

`run_sync()`、`run_stream()`、`respond_approval()` 各自 `Runtime::new()`，用完隐式 drop。浪费线程池初始化成本，增加延迟。

**建议**：`OnceLock<Runtime>` 或 `lazy_static` 共享。

### H3. Webhook Server 手动解析 HTTP

**文件**：`crates/agent-runtime-core/src/run/webhook.rs`

原始 TCP socket + 字符串匹配解析 HTTP（Content-Length 分片、header 解析、body 切分），不支持 chunked encoding / keep-alive。

**建议**：引入 `hyper`、`tiny_http`，或至少 `httparse`。

### H4. MCP HTTP Client JSON-RPC ID 硬编码为 `1`

**文件**：`crates/agent-runtime-core/src/tool/mcp.rs:350`

```rust
let body = json!({"jsonrpc": "2.0", "id": 1, ...});
```

Stdio client 用 `AtomicU64` 递增，HTTP client 硬编码 `1`。当前因串行调用而安全，但未来并发化会路由错误。

**建议**：对齐 stdio client。

### H5. Event Channel 容量 256 可能导致背压死锁

**文件**：`crates/agent-runtime-core/src/run/mod.rs:20`

```rust
let (event_tx, event_rx) = mpsc::channel(256);
```

消费者慢于生产者时 channel 填满，`tx.send().await` 阻塞 run loop 导致 token 超时。

**建议**：至少 `4096` 或 `unbounded` + 文档说明。

## Medium（改进建议）

### M1. `#[allow(clippy::result_large_err)]` 大量使用

`ModelError` 和 `ToolError` 各含 6-7 个字段，Clippy 警告被全局 suppress。热路径有栈复制成本。

**建议**：不常用字段（如 `upstream_body: Option<Value>`）放入 `Arc`。

### M2. `ToolContext` 应 derive `Clone`

**文件**：`crates/agent-runtime-core/src/tool/mod.rs:80-86`，`in_process.rs:64-70`

`InProcessTool::execute()` 手动逐字段复制 `ToolContext`。新增字段时容易遗漏。

**建议**：`#[derive(Clone)]` for `ToolContext`。

### M3. Python SDK 类型别名过宽

**文件**：`python/agent_runtime/__init__.py:9`

```python
JsonValue: TypeAlias = Any   # 太宽，失去类型检查价值
```

`.pyi` 文件已有精确定义，`__init__.py` 未同步。

### M4. `SearchToolsTool` 每次搜索 O(n×m) 比较

**文件**：`crates/agent-runtime-core/src/tool/search.rs:113-128`

对每个 tool 实时计算 trigram Jaccard 分数。500+ tools 时可能成为瓶颈。

**建议**：预计算 trigram sets 入索引。

### M5. `AgentDelegate` 无 `input_mapper`

**文件**：`crates/agent-runtime-core/src/tool/mod.rs:51-59`

有 `output_mapper` 无 `input_mapper`。`AgentTool` 在 `execute()` 中自己做了映射再构造 `AgentDelegate`。如果 `AgentDelegate` 被直接构造（绕过 `AgentTool`），映射丢失。


### M6. OpenAI-compatible adapter 消息序列化逐字重复

**文件**：`openai.rs:82-178`、`deepseek.rs:78-178`、`openrouter.rs:97-210`

OpenAI、DeepSeek、OpenRouter 三个 adapter 的 `Role::System`、`Role::User`、`Role::Tool` 分支逐行相同，合计 ~500 行重复。差异仅在 `Role::Assistant` 分支：

| Adapter | 差异 |
|---------|------|
| OpenAI | 跳过 `Thinking` blocks |
| DeepSeek | 额外写入 `reasoning_content` 字段 |
| OpenRouter | 处理 `reasoning_details` 数组 + `ContentBlock::Thinking` 的 `provider_details` |

Anthropic 走独立格式（native `tool_use`/`tool_result`），但另外三家是同一个 OpenAI-compatible JSON schema 的子集。每新增一个 OpenAI 兼容 provider（Groq、Together、Fireworks 等）都会复制这 ~170 行/文件。

**建议**：抽 `OpenAiCompatibleMessageBuilder`，各 adapter 只声明差异化的 assistant extras hook。

## 跨切面一致性审查

以下按 AGENTS.md 约定的项目逐项检查。

### 错误处理 — 基本合规

**✓** 各模块使用 `thiserror` 定义独立错误类型：`ToolError`（`tool/mod.rs`）、`RegistryError`（`tool/registry.rs`）、`McpError`（`tool/mcp.rs`）、`ModelError`（`providers/types.rs`）、`ScanError` / `EnvError`（`skill/mod.rs`）、`ScriptError`（`skill/executor.rs`）。

**✗ AGENTS.md 约定的 `BudgetError` 未实现**。`budget.rs` 只有 `BudgetViolation` 枚举（非 `thiserror`），没有 `BudgetError` 类型。预算超标通过 `RunFailed { error: "budget_exceeded" }` 字符串传播，丢失结构化信息。

### `unwrap()` / `expect()` — 合规

库代码中仅 `tokenizer.rs:11` 有一处 `expect()`，有 `//!` module doc 说明 invariants。其余全部在 `#[cfg(test)]` 内。✓

### `unsafe` — 合规

仅存在于 `#[cfg(test)]` 块内（`executor.rs:183`、`mcp.rs:762`），用于测试中检查子进程存活状态。库代码零 `unsafe`。✓

### 阻塞 I/O 未包裹 `spawn_blocking` — 部分违规

**✗ `skill/mod.rs`**：`SkillScanner::scan()` → `scan_recursive()` 直接调用 `std::fs::read_dir()`；`parse_skill_md()` 调用 `std::fs::read_to_string()`、`std::fs::canonicalize()`。这些被 async 函数 `register_skills()` 调用但不经过 `tokio::task::spawn_blocking`。

**影响**：scan 只在启动时执行一次，文件量通常不大，阻塞时间短。但严格违反 convention。

### 序列化 — 合规

`RuntimeEvent`、`RunState`、`AgentConfig`、`BudgetConfig`、`JobHandle`（手动 impl）等跨 FFI 类型全部实现 `Serialize + Deserialize`。✓

### `mod.rs` 职责 — 部分违规

| 模块 | 状态 | 说明 |
|------|------|------|
| `run/mod.rs` | ✓ | 仅 re-export + `AgentRun::start()`，58 行 |
| `tool/mod.rs` | ✗ | 含 `Tool` trait + `ToolOutput` + `AgentDelegate` + `ToolMetadata` + `ToolContext` + `ToolError` + `ToolCall`，111 行。应拆出 `types.rs` |
| `skill/mod.rs` | ✗ | 含 `SkillManifest` + `SkillScanner` + `CapabilityValidator` + `SkillEnvManager` + 所有 raw 类型，604 行。应每个 struct 一个文件 |
| `model/mod.rs` | ✗ | 27 符号 blanket re-export + 1 alias。违反 "Do not blanket re-export" 约定 |

### 命名 — 合规

类型 `PascalCase`（`ToolMetadata`、`ModelAdapter`），方法 `snake_case`（`execute()`、`run_id`），常量 `SCREAMING_SNAKE_CASE`（`ALLOWED_EXECUTABLES`、`SENTINEL_PREFIX`、`DEFAULT_TIMEOUT_SECONDS`），测试 fakes `Fake*` 前缀。✓

### Feature flags — 未使用

当前无 feature flag，所有功能编译进单一 binary。随 provider 数量增长应考虑 `anthropic` / `openai` / `deepseek` / `openrouter` feature gate 以便按需编译。
