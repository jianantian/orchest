# Orchest 0.3.0 · 发布计划

Rust、Python 和 Node 的下一次公开发布统一为 `0.3.0`，沿用现有的 crates.io、PyPI 和 npm 包名。三个内部迭代分别实施、验收和合入，候选版从同一个源码提交选定本次公开范围。

## 候选范围

| 内部迭代 | 候选交付 |
| --- | --- |
| [运行控制](../archive/iteration/runtime-controls/prd.md) | Python / Node 异步运行、事件迭代、按运行取消和回复、本地会话恢复。Node 补齐 Agent-as-Tool 与内建写文件工具。 |
| [语音能力](../iteration/voice-capabilities/prd.md) | ASR / TTS 能力目录与用量计量、Rust TTS 双工、Python / Node TTS 接口。按方言记录已验证的追加文本、Flush、取消与关闭行为。 |
| [SDK Session 证据](../archive/iteration/sdk-session-evidence/prd.md) | Python / Node 显式开启本地采集和分页查询尝试元数据。Rust 已发布的可选证据功能继续随版提供。 |

确定候选提交时，按独立可交付的能力决定纳入范围。纳入项须满足自身的迭代契约及跨端依赖，并通过候选包验证。未就绪的能力留待后续版本，并从本版公开产物的 API 和能力声明中排除。SDK 轨迹须在 Python 和 Node 都通过采集授权、会话隔离、元数据白名单和恢复回归后一起公开。

### 运行控制验收基线

运行控制在 Rust workspace `0.3.0` 源码上复用 v2.0 Runtime 契约和 Session v2 日志。本地行为和性能验证使用 macOS arm64 上的 Rust 1.99.1、CPython 3.14.8、Node 22.22.2。发布候选需记录对应的源码提交、SDK 构建矩阵结果与安装验证。异步运行和会话恢复的本地测量分别记录于 [001](../archive/iteration/runtime-controls/issues/001-async-run/plan.md) 和 [003](../archive/iteration/runtime-controls/issues/003-session-resume/plan.md)。

## Rust 发布历史

2026-11-26 已核对 `orchest`、`orchest-protocol`、`orchest-storage`、`orchest-provider`、`orchest-provider-core`、`orchest-provider-http`、`orchest-provider-stream`、`orchest-provider-visual` 均已从 crates.io 删除。注册表 API 和 Cargo 索引均返回 `404`。Git 标签和源码记录作为归档。

### 补发 Rust 0.2.0

Rust `0.2.0` 取自已发布的 SDK `0.2.0` 源码，八个 crate 已于 2026-11-28 发布到 crates.io。Python 和 JS 继续使用已发布的 `0.2.0`。[Rust 0.2.0 发布](https://github.com/jianantian/orchest/releases/tag/v0.2.0) · [发布验证](https://github.com/jianantian/orchest/actions/runs/46033342490)

## 版本与标签

| 构建 | Rust 标签 | Python / Node 标签 | 注册表版本 |
| --- | --- | --- | --- |
| 首个候选版 | `v0.3.0-rc.1` | `sdk-v0.3.0-rc.1` | Rust / npm 为 `0.3.0-rc.1`，PyPI 为 `0.3.0rc1` |
| 正式版 | `v0.3.0` | `sdk-v0.3.0` | 三端均为 `0.3.0` |

每组标签指向同一个提交。Rust 工作区、Python 包、npm 主包和平台包使用同一版本，npm 主包精确依赖同版的平台包。发布工作流检查版本、标签、平台依赖和 changelog。npm 候选版使用 `next`，正式版使用 `latest`。[Rust 工作流](../../.github/workflows/release.yml) · [SDK 工作流](../../.github/workflows/release-sdk.yml)

## 发布顺序

1. 用同一候选提交构建三端，跑 Rust 工作区检查及 Python / Node 的三平台打包测试。把候选版已经验证的交付范围、迁移事项和各方言的语音能力写进发布说明。
2. 先发 Rust 候选 crate，再从同一提交发 Python 和 Node 候选包。通过 crates.io、PyPI 和 npm 安装指定版本，验证 Linux x86_64、Linux arm64 和 macOS arm64 上的公开产物，包括 npm 主包安装后能加载对应原生平台包。
3. 候选版通过后，以统一的 `0.3.0` 版本从正式提交按同一顺序发布，再从三个注册表复验安装、版本和各端功能入口。
