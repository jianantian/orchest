# WorkBuddy（腾讯）竞品研究

> **观测时间:2026-06-26 ｜ 观测版本:5.1.6（2026-06-23 发布,三天前）**
> 性质:迄今最重量级的**同向竞品**——同时占据「监督 / AI 员工」与「团队知识」两个侧翼。
> 上游:ADR-001 §5.5.1 竞品地形图（该文档已随 Multivac 分析清理归档移除,本文保留作为独立竞品研究）
>
> **方法论警告(本文存在的前提):WorkBuddy 周更,bug 清单没有保质期。** 3 月 9 日上线、6 月 23 日已到 5.1.6,光 6/14–6/18 一周修 50+ 项。因此本文严格区分**成熟度(快变、在修、不构成壁垒)**与**结构(设计命题、稳定、定义竞争边界)**——只有后者能用来判断竞争。成熟度部分仅作时间快照,过期即作废。

## 0. 一句话

**WorkBuddy = 让现有组织里的人,更快产出现有组织本来就要的那些文档(报告 / PPT / 调研 / 日周报)。** 它提的是**现有工作形态下的效率**,不改变工作是什么、由谁来做。这一句是理解它全部用户、场景、反馈的总钥匙。

它自己的定位坐实了这一点:
- **愿景**:「让每位知识工作者拥有『能干活、可交付』的 AI 同事」——AI **同事 / 员工**心智,不是创作伙伴。
- **官方痛点**:**「老板要个 PPT,我不想自己做」**——这一句直接自证了 §2 的判断:它瞄准的是**老板派下来的商品化交付物**,不是个体想做的原创工作。这恰好是 ADR §0.6 否定的「空心老板模型」的执行端。

## 1. 真实用户群体(核心)

| 维度 | 事实 |
|------|------|
| **是谁** | 非技术办公岗:HR / 行政 / 秘书 / 运营 / 销售 / 市场。腾讯内部 2000+ 验证盘就是这批人。 |
| **不是谁** | 不是开发者(那是同生态的 CodeBuddy)、不是创作者。是「每天和文档 / 表格 / 邮件 / 内部知识库打交道的 desk worker」。 |
| **为什么是他们** | 上手门槛极低锁定了这个群体:傻瓜式、点预设不用配置、IM(企微 / 微信 / QQ)遥控。对不写代码、不懂 prompt 工程的人,这是第一个「装上就能用」的 agent。 |
| **企业版指向** | 把这些「数字员工」成建制铺进组织(专家 → 助理 → 团队三层),目标是组织级的能力沉淀与复用,而非个体。 |

**判断**:它的用户画像与我们(D5 builder / 创作者 / OPC / 小组织)**几乎不重叠**。它服务的是「在大组织里做重复性交付物的执行岗」,我们服务的是「做原创工作的创作单元」。

**与 CodeBuddy 的关系(同底座双产品)**:WorkBuddy(非技术岗)与 CodeBuddy(程序员 / 架构师)**共享同一自研 Agent 底座、同一 Skills 体系、同一混元 Hy3 模型层**;WorkBuddy 的代码 100% 由 CodeBuddy 生成(内部 dogfooding)。即腾讯用「一套 Agent runtime,两个受众皮肤」覆盖技术 + 非技术全场景——这是它的分发优势,也意味着 runtime 层对它是已摊销的固定成本。

## 2. 真实使用场景(核心)

真实反馈里,场景泾渭分明地分成两堆——这个分界就是 WorkBuddy 的能力边界:

### 2.A 它真正好用的:商品化交付物(有模板、可重复、低风险)

- 周报 / 日报自动生成;定时抓取微博 / 知乎 / 小红书热点 → 分类 → 生成日报 / 周刊
- 数据分析图表、报告、PPT、海报、营销文案
- 会议纪要整理、竞品信息抓取、按频率跑的后台自动化任务

这些都是**产出形态固定、对错容忍度高、不需要原创判断**的活。WorkBuddy 在这里确实压缩了「产出标准办公制品」这一步。

### 2.B 它做不好的:非平凡工作(新颖、多步、高风险、要真行动)

- **复杂多步任务跑偏**:「要么数据算错、要么文案写偏」,需要人工盯 + 返工——**这是最高频的真实抱怨**
- **实时数据 + 第三方真联动落不了地**:实时金价盯盘 + 微信推送这类,只能给「理论思路」
- **一对话多任务会混乱**:同一对话塞写报告 + 改 PPT + 分析数据就理解混乱(上下文管理偏浅)

**判断**:WorkBuddy 的甜点是「商品化制品的快速初稿」,天花板是**任何非平凡任务的正确性**。这正是「现有组织形态下提效」这个定位的必然边界——它优化的是产出环节,不触碰判断与创造。

**一个识别种子内容的标尺**:网上「实测**半年**」类文章是假的——产品到今天才 3.5 个月。正面博客圈(周报 2 小时→1 分钟、效率提升 300% 等口径逐字重复)大量是种子 / 通稿,需打折看待。**真正有信息量的是负面反馈的一致聚类**——不同作者独立踩到同一批坑。

### 3.1 成熟度反馈(快变,在修,**别据此判断竞争**)

3–4 月的具体 bug 抱怨,6 月 changelog 显示正被极快修掉:

| March–April 抱怨 | 6 月状态 |
|------------------|---------|
| 大文件列表导致会话卡死 | ✅ 已修 |
| Windows 中文用户名 / macOS 兼容 | ✅ 已修 |
| 权限弹窗反复弹出 | ✅ 已修 |
| 一对话一任务 / 上下文丢失 | 🔧 优化中(压缩策略、会话切换保留历史) |
| 模型切换繁琐 | ✅ 对话内可直接切;内置 11 种国产模型 + 自研混元 Hy3 模型层,支持 Auto 自动选模型 |
| 过程不可见 | 🔧 加了**只读遥测**(工具调用进度、「思考」标记、发送时间) |
| 复杂任务无纠偏 | 🔧 工具循环检测黑名单机制 |

**注**:它修的「工具循环检测」「上下文压缩」正是 Orchest 早已有的 `LoopDetectionHook`(v0.7)与 context compaction(v0.2)。**runtime 层在商品化,差异化不在这层。**

> 结论:稳定性 / 兼容 / 上下文这些,**假设会收敛到「扎实」,不要赌它不行**。把这些当竞争判断会犯时间错误。

### 3.2 结构反馈(稳定,定义竞争边界)

这些是**设计命题,不是 bug**,迭代不会改——这才是竞争该盯的:

1. **黑盒「结果交付界面」范式**。一篇深拆点破:它「把 Agent runtime 换成了结果交付界面」。6 月新增的「过程可见性」全是**只读遥测**(看它思考、看进度条),不是 deixis、不是中途干预、不是共创。**人的角色是验收一个黑盒交付物**。#1 抱怨(跑偏→返工)正是这个范式的必然代价:黑盒错了,人只能拒收重提,没法在过程里早早纠偏。
2. **云端 + 腾讯生态锁定,且在加深**。「专家搬进云端办公室」;已打通 QQ 邮箱 / 腾讯文档 / 腾讯会议 / 企业微信 / 乐享 / 微云 / ima / TAPD,加上 SkillHub + MCP + 专家中心。沉淀绑定这整套腾讯办公栈,**不归用户**。隐私 / 本地化 / 审计是多篇文章公认「没讲清」的点。生态越打通,锁定越深——这是它的护城河,也是它结构上无法走向「本地拥有」的原因。
3. **保持现有组织形态**。Teams 层是「把数字员工塞进现有组织图」,优化协作,不是工作转型。
4. **商品化交付物焦点**。每个版本加更多商品技能(6-23 加财报数据技能、日 / 周报自动化)——**往地板挖深、往组织铺宽,不往新颖 / 原创 / 共创爬**。

### 3.3 采用与商业(真实信号)

- **采用障碍**:大公司担心本地文件操作导致数据泄露;中小企业对 AI 工具付费意愿低。
- **额度 / 定价**:免费 5000 credits,多模态任务烧得快;定价未公开(早期阶段)。
- **区域局限**:中国 / APAC 优先,无 Slack / Teams / Google Workspace 集成,非腾讯系(WPS / 飞书 / 钉钉)兼容差。
- **弃用风险真实**:共识是「用对了有长期价值,用不对就变鸡肋被弃用」——需要正确设置与理解才不被抛弃,这本身是上手心智成本。

## 4. 对我们(Multivac)的含义

1. **用户的核心判断被验证**:WorkBuddy 证明「商品化交付物提效」这个市场真实且大(腾讯压了全套资源),但也暴露了它的天花板——**非平凡工作的正确性 + 人当黑盒 QC 的挫败感**。
2. **我们的赌注恰好治 #1 抱怨**:共创介质 + deixis + attended 阶段一 + 过程可见可干预,正是解「跑偏 / 返工 / 无法中途纠偏」的解药。但只在「正确性 / 原创性 / 拥有权值得为共创买单」的工作上成立。
3. **别去抢商品化地板**:大部分办公产出就是周报这种制品,「够用 + 免费 + 1 分钟装好 + 腾讯分发」在这个段位会赢过「更好但更费劲」。我们的楔子是创作者 / OPC / 小组织的**原创工作**,不是和它抢 desk worker。
4. **钳形地形定位**:WorkBuddy 是「监督 + 团队知识」两侧翼迄今最重量级的占据者(分量 > Multica:腾讯分发 + 五垂类已跑出营收)。但它的结构性缺位反向确认——**「共创 × 执行 × 本地拥有」的交点仍空**。
5. **对 thickness 论的修正**:我们不能再把「有沉淀」当护城河——WorkBuddy 的「上下文飞轮」已在规模上把沉淀产品化。差异化必须收紧成**「沉淀是本地拥有的、从共创投影出来的,而不是云端的任务日志」**。

## 5. 威胁升级触发条件(监控清单)

> 这是对一个**周更产品**保持文档保质期的方式:不盯它修没修 bug,只盯它有没有跨过下面任一**结构性**红线。跨过任一条,本文作废、立即重估。

1. **加入真正的中途干预 / 指**——不只是只读进度条,而是能在过程中指着某个产物 / 步骤重定向(从黑盒交付转向共创)。
2. **给出本地拥有 / 可导出沉淀的承诺**——沉淀脱离腾讯云锁定。
3. **从商品交付物上移到新颖 / 原创 / 共创工作**——技能矩阵不再只是日周报 / 报告 / PPT。
4. **出海打通 Slack / Teams / Google + 非腾讯生态**——直接进攻全球创作者 / OPC。
5. **开放 / 自托管形态**——打破生态锁定。

**截至 5.1.6:五条全部未触发,且 1 / 2 / 3 在反向加深(只读遥测、云端绑定、商品技能)。** 这是当前对我们最有利的事实。
