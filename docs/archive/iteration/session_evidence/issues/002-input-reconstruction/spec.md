# 002 · 受控采集与重建 adapter 输入

GitHub issue: #359

## 背景

每次 `before_model` 从干净的历史构造临时输入。相同的 step 和配置可以对应不同输入。

## 目标

在 001 的 Rust 读取路径上按尝试查看配置覆盖状态，并在显式授权下重建有序消息、工具定义和 options。依赖 001。

## 验收标准

- [ ] 受控 mock adapter 在同一 step 的两次尝试收到不同 hook 注入。重开证据存储后，分别重建的消息、工具顺序及 options 与 mock 实收对象逐项相等；原 Session 恢复后未出现临时注入。
- [ ] 等值配置经内容复用时，两个有效上下文仍可区分。同值内容在不同会话实例、捕获策略或权限范围下分别校验。保留调用边界能表达的工具顺序与参数区别；上游已合并的状态保持未知。
- [ ] adapter 报告的调整与调用时传入值分别显示。缺失、裁剪、脱敏或被拒绝的字段带覆盖标记。只有覆盖完整且允许读取时才报告所声明范围内的精确重建。
- [ ] 用合成凭证、私有内容、自定义 JSON 和附件测试字段白名单。策略禁止的值在进入队列和持久存储前被排除。处理超限输入时停止采集并记录覆盖状态，避免复制或排队整份超限对象。
- [ ] 控制写线程以覆盖撤销发生在写入排队期间的情况。撤销或过期生效后，旧引用不可再读取，积压的写入不能恢复权限；清理对应持久内容和索引。检查现有遥测没有证据正文。
