# 002 · 按运行控制与公开事件类型

## 背景

SDK 0.2 的 `abort`、`respond` 与 `capabilities` 已存在。新运行对象需要持有唯一的控制目标，并以两端一致的形状表达核心事件与错误。

## 目标与范围

透传 v2.0 控制契约，定义公开事件、请求回应、取消原因和能力。在 001 的生命周期错误之上补充运行控制错误。

## 验收标准

- [ ] 批准、拒绝、带结构化答案的请求都按其 ID 回复。向另一运行、过期或已回答的请求 ID 发送回复时，调用方能区分请求未找到与非法响应格式。
- [ ] 待审批时进程退出，恢复会话并重新发起审批后，旧请求 ID 返回 `request_not_found`，新请求仍等待回复。
- [ ] 取消等待审批或模型流中的运行时，第一次成功取消返回真，后续取消返回假，终止事件携带同一核心原因。
- [ ] 两个 Agent 同时运行时，一方的回复、结束或取消不改变另一方。能力对象来自目标 Rust 句柄。
- [ ] Python 和 Node 用已安装包的公开运行入口执行同一测试场景，逐项将实际输出与 Rust 生成的预期事件序列比对，覆盖顺序、判别字段和典型 payload。新增或遗漏 canonical 变体会导致契约检查失败。新 Run 事件流中的子运行包装事件递归提供相同的判别字段。
