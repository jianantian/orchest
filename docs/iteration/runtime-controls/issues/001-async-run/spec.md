# 001 · 异步运行对象与事件迭代

## 背景

Python `run` 收集完事件才返回。Node 的 callback 路径在绑定里调用 `block_on`。两端已有各自的运行句柄槽位，缺少统一的运行生命周期。

## 目标与范围

提供独立于宿主事件循环的运行对象。默认顺序为启动、异步消费至结束、取得结果。等待方法在事件流耗尽前立即返回可恢复的类型化错误，保持事件流和运行可用。调用方可继续消费或显式关闭。取消请求发出后仍可消费终止事件，提前关闭则取消仍活跃的运行并释放事件接收器。

## 验收标准

- [ ] 在模型 fixture 暂停产出时，运行对象已经可用，异步迭代能读取第一个事件，Python `asyncio` 与 Node 定时器可继续运行。
- [ ] 缓慢消费时，中途暂停再恢复得到与 Rust canonical 输入同序同量的事件，跨绑定队列保持有界。
- [ ] 同一 Agent 的同步、回调和异步入口竞争时只有一次启动成功。第二次启动返回可识别错误，原运行的句柄保持可用。不同 Agent 独立运行。
- [ ] 正常耗尽后能取得结果。未开始迭代、队列已满、收到终止事件但尚未耗尽时，过早等待均立即返回同类可恢复错误。之后继续消费，仍能取得完整事件与结果。
- [ ] Python 退出异步上下文或显式关闭、Node 提前终止事件迭代、首次读取失败时，释放接收器并清理读等待项。重复关闭安全，运行实际结束后释放 Agent 占用。满队列下同样可取消并退出，取消后继续读的调用方仍能收到终止事件。
- [ ] 固定负载下记录首事件延迟、吞吐、队列峰值和取消响应时间，覆盖持续消费、慢消费者和满队列退出。空闲接收器无轮询，队列满时内存不会随事件总数增长。
- [ ] SDK 0.2 的成功调用方式、返回形状与已有测试保持可用。

## 依赖

Rust v2.0。
