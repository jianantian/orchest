# 002 · 语音计量与成本估算

## 背景

流结束事件目前携带 `TokenUsage`。Provider-core 已有毫秒计价和 `Cost`，没有面向语音的统一用量与字符计价。Rust 职责是给出可核对的用量和估算依据。

## 目标与范围

为语音增加类型化用量通路与字符计价，明确上游报告、对已知输入的估算及未知值的编码。

## 验收标准

- [x] 在终止或结算路径中，调用者可读到具体 provider/model、音频时长或字符数、来源及可用的币种和成本估算。相同流的结算数据只发布一次。
- [x] 有上游用量时按其语义透传。可按输入格式可靠计算时，已知长度 fixture 得到可复算估算。缺失计量、定价或格式信息时，相应字段保留未知。
- [x] Unicode 与分段文本由 fixture 验证计数单位。记录 provider 自报的计费单位；本地估算使用公开的计数规则，标明估算来源。
- [x] 取消、失败及正常结束可以区分。重试和空增量 fixture 不会凭空增加用量。已有 LLM token 结算和 ASR 事件使用方式通过回归测试。

## 依赖

001 的模型身份和定价字段。

## 结算契约

- 一次性成功结果的 `voice_usage` 和流的 `EventStream::take_voice_usage()` 使用同一类型。流读取到终止事件或 EOF 后可以取一次结算。ASR transcript / lifecycle 和 LLM token 事件沿用当前顺序和数据。
- 时长统一为毫秒，来源区分厂商处理量、厂商计费量与本地输入估算。厂商累计数字取最后一个有效值。已知 PCM 字节数按配置的采样率及声道换算，完整 PCM WAV 按头信息与数据块换算。
- 本地 TTS 字符数按 Unicode 标量值计数，包含空格和标点。上游计费字符单独标注。只有目录报价及计费单位适用时才生成成本估算。
- 流成功结束、显式 Interrupt 和失败分别结算。连接失败由原调用返回错误。处于失败或取消状态的用量可以反映已发送的部分，成本仅在正常完成且计价依据适用时推算。
