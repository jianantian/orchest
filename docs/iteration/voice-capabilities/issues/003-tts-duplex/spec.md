# 003 · 三个 TTS 方言的双工契约

## 背景

三个 TTS adapter 的整段输入路径能返回流式音频，`start_duplex_stream` 仍返回 `UnsupportedOperation`。ADR-0006 D7.5 允许将 Finalize 映射为 Flush，并以 Turn 表达合成上下文结束。

## 目标与范围

逐个验证 Aliyun、Volcengine、MiniMax 的追加文本、Flush、取消上下文和关闭。目录按验证结果声明能力，单个方言缺少某项能力时可独立验收其他方言与操作。

## 验收标准

- [ ] 对每个声明双工的方言，可控 transport fixture 在输入仍开放时产生音频，后续文本仍可追加，音频可归属到对应上下文，关闭释放资源。已声明的 Flush 才要求可验证的音频边界，缺少词级对齐信息时对应字段可省略。
- [ ] 对声明 Flush 的方言，接受与完成可区分，完成事件只在当前边界可证明时发出，下一段输入仍可继续。若通过结束并续接 provider task 映射，fixture 明确证明上下文归属和顺序。
- [ ] 对声明取消的方言，确认后旧上下文后续到达的音频不再交付。双工关闭和重复关闭可完成且释放 transport。握手失败、断连或不支持的操作返回明确错误。
- [ ] 能力矩阵逐方言、逐操作记录支持、不支持和待验证三种状态及其证据。声明支持须有协议依据与契约 fixture，并记录真实服务验证覆盖。仍待验证或已知不支持的操作从能力声明中排除，同时验证清晰的错误路径。

## 依赖

协议验证依赖 v1.2，目录及计量接线依赖 001、002。
