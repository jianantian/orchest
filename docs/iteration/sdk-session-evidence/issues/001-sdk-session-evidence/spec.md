# 001 · Python / Node 的本地 Session 证据

## 背景

Rust 的可选 `session-evidence` 在 0.2.0 已交付，借鉴 DSH 的做法记录逐次模型调用。它有独立的本地存储、按会话实例绑定的查询，以及宿主授权后的输入重建。Python / Node 宿主在排查重试或失败时需要看到尝试的元数据。[Session 证据 PRD](../../../../archive/iteration/session_evidence/prd.md)

## 目标与范围

- 复用[运行控制 003](../../../../archive/iteration/runtime-controls/issues/003-session-resume/spec.md) 提供的本地存储与会话配置，通过现有 Rust 证据层采集。每个运行显式启用，恢复已有 Session 时也需重新选择。
- 读取句柄在授权时固定到存储和会话实例。删除、同名重建或撤销后旧句柄失效，重新授权后才能读取新的实例。以类型化的尝试开始和结束记录为基础，公开尝试 ID、运行 ID、步骤、顺序、可用的 provider / model 与结果分类。调用方可用尝试 ID 跨页关联。
- 页结果提供绑定到当前实例的不透明游标及核心能报告的缺失信号。筛选后记录可以为空，以没有下一页游标作为分页结束条件。有游标时须向前推进。结束记录不可用时，结果保持未知。沿用核心的读取上限、保留期和撤销规则。
- 两端 API 只从允许的记录类型显式映射字段。提示词、模型和工具正文、凭证、内容引用以及全文重建均留在现有 Rust 授权边界内。采集或读取故障由证据层报告，Session v2 仍沿原入口恢复。

## 验收标准

- [ ] 两端使用临时本地存储验证新运行默认关闭采集。已启用采集的会话在恢复时，只有宿主再次显式启用才会记录新运行。
- [ ] 同一步骤先失败后成功时，分页结果可按两个不同的尝试 ID 读到结果。开始与结束跨页仍可关联。结束记录缺失时结果为未知，核心报告丢弃时页状态明确标记证据可能不完整。
- [ ] 不同存储中的同名会话和同名重建的新会话都读不到旧记录。删除、重建或撤销后，已有句柄返回明确的失效状态，旧句柄也读不到新实例。新实例重新授权后可正常读取。
- [ ] 使用含模拟授权内容与引用的 Rust 证据库验证 Python / Node 返回值。序列化结果只含允许的元数据。两端对越界页大小统一返回参数错误，对无效或属于其他实例的游标统一返回游标错误。
- [ ] 一页原始记录全部被过滤时仍返回可推进的下一页游标，并能继续读到后续的尝试记录。用固定扫描上限验证单页读取工作量与内存受限。
- [ ] 注入采集或读取故障后，已有 Session 的恢复与追加输入通过。Rust 的采集、分页和授权重建通过原有回归。
- [ ] 两端用三个目标平台的本地构建产物完成最小启用与分页查询示例。SDK 指南说明启用方式、返回字段、跨页关联、空页继续条件与未知状态。
